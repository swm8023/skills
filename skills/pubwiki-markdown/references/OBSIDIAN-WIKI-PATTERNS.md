# Obsidian Wiki Generation Patterns

本文件是 `pubwiki-markdown` 的本地生成策略。它补充上游 Obsidian 语法参考：语法参考说明“怎么写”，本文件说明“什么时候值得写”以及怎样把新笔记接入已有知识网络。

## 核心原则

生成 Wiki 页面时，不要把任务理解为“生成一份孤立的 Markdown 摘要”，而要把页面当作知识图中的一个节点：

1. 先检查已有笔记、标题、`aliases`、标签和相似内容。
2. 识别本页面与已有页面之间有事实依据的关系。
3. 使用少量高价值的内部链接建立关系。
4. 识别已有页面是否应该反向指向本页面。
5. 把出链、反向链接和 Obsidian 特性选择写入同一份完整预览。

链接的语义必须来自内容，而不是只因为两个页面共享一个关键词。没有合适的关系时，宁可不加链接。

## 链接与反向链接策略

### 内部笔记

- 已确认存在的 Vault 内笔记默认使用 `[[Note]]`，而不是普通 Markdown 链接。
- 需要更自然的显示文本时使用 `[[Note|显示文本]]`。
- 需要指向具体内容时使用 `[[Note#Heading]]`；只有目标稳定且值得复用时才添加 `^block-id`。
- 每篇普通笔记通常加入约 2–5 个高价值出链；索引/导航页可以更多。这个数量是质量提示，不得为了达标制造关系。
- 正文中适合表达关系时使用自然的上下文链接；链接会使正文变得嘈杂时，使用 `## 相关笔记` 小节集中列出。
- 外部网页、仓库或服务继续使用普通 Markdown 链接。

### 目标确认

- 只链接到已确认存在的笔记，或已经纳入本批次目标路径映射的笔记。
- 批量导入时，先建立来源到目标的路径映射，再改写 Wikilinks、标题目标、块目标和资源链接。
- 在预览中列出无法解析的本地链接、重复目标和资源冲突；不要用猜测的标题掩盖它们。
- 不在代码块、行内代码或引用的源代码示例中改写链接形状文本。
- 草稿或私有笔记不得从公开笔记中建立链接，除非用户明确确认这种关系。

### 反向链接

Obsidian 的 Backlinks 不是需要写入的字段，而是由其他笔记指向当前笔记的内部链接自动派生出来的。因此：

- 新页面的出链会自然增加已有目标页面的反向链接。
- 对于重要的新主题，检查同一 repo 中直接相关的已有笔记是否应该增加指向新页面的链接。
- 只有关系清晰、能改善未来检索或导航时，才提出已有笔记的反向链接修改。
- 反向链接修改必须作为当前完整预览的一部分展示，并与新页面一起获得确认；不得静默修改已有笔记。
- 不为了追求双向对称而强行让每一条链接都返回，也不批量改写整个 Vault。

## 特性选择规则

| 特性 | 适合使用的场景 | 生成约束 |
| --- | --- | --- |
| `[[Wikilinks]]` | 关联概念、项目、组件、决策和参考页面 | 内部目标优先使用；目标必须可确认 |
| 标题/块链接 | 引用某个具体章节、决定或稳定结论 | 只在精确定位有价值时使用；块 ID 要稳定、可读 |
| Properties | 标题、描述、日期、状态等可筛选的结构化元数据 | 优先复用当前 frontmatter；不要为了关系新增必需字段 |
| `aliases` | 缩写、常用别名或多语言名称 | 仅保留来源已有或用户确认的别名；不添加空数组 |
| 层级标签 | 主题、领域或生命周期等稳定分类 | 复用已有规范标签；新标签仍需确认 |
| Callout | 决策、约束、警告、开放问题、成功条件 | 按语义使用；不要用自定义类型替代普通结构 |
| Embed | 需要复用的稳定章节、块、图片或文档资源 | 目标和资源必须存在，并在预览中说明；避免重复整篇内容 |
| Bases、Canvas、Dataview | 需要额外文件格式或插件的高级视图 | 不作为默认生成内容；只有用户明确要求时再单独设计 |

特性选择应服从内容，不应为了展示语法而添加 Callout、Embed、块 ID 或标签。已有来源中的合法 Obsidian 语法应按主 Skill 的规则保留，除非目标链接映射或渲染器要求安全等价写法。

## 生成时的关系检查

在准备预览前，逐篇记录以下结果：

- **关联目标**：候选笔记、目标路径、关系理由和是否已确认存在。
- **新增出链**：本页面实际加入的 Wikilinks、标题目标或块目标。
- **反向链接建议**：需要更新的已有页面、拟插入位置和理由；没有建议时明确写“无”。
- **特性选择**：使用了哪些 Properties、标签、Callout、Embed，以及为什么没有使用其他特性。
- **风险诊断**：未解析链接、重复目标、资源冲突、草稿/私有边界和兼容性影响。

预览可以采用以下结构；它不产生额外确认轮次：

```markdown
### Obsidian 特性建议

- 出链：[[Existing Note]]（关系理由）
- 反向链接：更新 `content/repo/existing.md`，加入指向当前页面的链接（理由）
- 结构：使用 `status` 属性和 `warning` Callout
- 资源：嵌入已确认存在的 `assets/diagram.png`
- 跳过：没有稳定目标，因此不添加块引用
- 诊断：未解析链接 0；重复目标 0；资源冲突 0
```

## 兼容性边界

- 当前 `title`、`description`、`date`、`tags`、`draft` frontmatter 和路径/发布规则继续有效。
- 页面关系优先通过正文 Wikilinks 表达，不引入必需的 `kind`、`slug`、`project`、`projects`、`references` 或 `backlinks` 属性。
- Block references 是 Obsidian 专有能力；生成它们时要在预览中接受较低的跨平台兼容性。
- Quartz 公开渲染依赖其已启用的 Obsidian Flavored Markdown、Backlinks 和 Graph 插件；不要假设普通 GitHub Markdown 页面也会呈现这些交互。
- 所有新特性都必须保持可审阅、可回滚，并遵循现有的重复检查、链接映射和一次性预览确认流程。
