# write-doc

## 调用约定

默认对新写或重组的文稿执行成稿后中文优化。用户或调用方可以明确要求跳过，调用方也可以为本次文稿传递 `optimize_zh: false`；当前文稿或调用方明确声明文稿供 Agent 阅读时，也默认跳过成稿后优化。仅提到 Agent 不代表受众声明。该决定只作用于交接的当前文稿，不延续到其他文稿或后续调用。

用户明确要求执行中文优化、润色或使用 `optimize-zh` 时，照常执行优化，即使调用方指定跳过或文稿面向 Agent。要求写作或修改正文不自动等同于要求成稿后优化。用户要求只审阅或提出修改建议时，按标注模式审阅，不改正文。跳过优化不跳过写前参考、基本审校或适用的独立复核。

写前比较同目录文档只在材料存在且允许访问时进行；没有可用的同目录或可比文档时，使用已提供的材料，不扫描授权范围之外的内容。

## 流程

按下面的顺序完成任务。

1. **按任务读取参考。**
   - 新写或重组技术文档（含 RFC、README）：先读 [write-technical](references/write-technical.md)，再读 [write-zh](references/write-zh.md)，然后起草。
   - 新写或重组其他中文文档、PR 描述或 commit message：先读 [write-zh](references/write-zh.md)，然后起草。
   - 润色已有稿：按第 2 步优化。只审阅已有稿：读 [optimize-zh](references/optimize-zh.md) 并使用标注模式，只返回问题或无问题的结论，不改正文，也不返回全文。
   - 仅绘图或修改图：读 [Mermaid](references/mermaid-diagrams/index.md)，再按图类型读取其中的参考，完成绘图后交付。
2. **完成正文并优化。** 初稿完成后，按调用约定决定是否优化；已有稿有明确润色要求时也执行优化。需要优化时调用子代理，让它读取 [optimize-zh](references/optimize-zh.md) 并处理文稿。交接当前稿件或授权文件路径、受众、编辑范围、必要依据和受保护内容；只提供允许披露且完成任务所需的材料。子代理只读取该参考、其按需引用的写作参考及交接中明确提供的材料与路径，不启动 Git 工作流，也不派生子代理。用户授权修改文件时，子代理可在指定文件和范围内直接修改；粘贴文本返回改写稿。保留可供对照的优化前稿件，等待子代理完成后核对结果；期间主代理和其他子代理不并发修改同一文稿。子代理不可用时由主代理按相同约束处理，并说明未由子代理优化。

   无论是否跳过优化，都检查事实、限定和受保护内容，不为润色补造信息。参考中的示例只展示写法，新增的具体条件或结果须有任务材料支持；删词时除检查通顺，还要保留信息和限定。写作中需要图示时，按第 1 步的绘图分支读取参考。
3. **独立复核完整文档。** 新写、重组或全面润色文章、RFC、README 等完整文档时，优化完成或确认跳过后，按 [review-doc](references/review-doc.md) 调用未参与起草和优化的只读子代理，检查成稿和适用流程；处理问题后再交付。简短润色、只审阅、PR 描述和 commit message 默认自行核对，用户要求独立复核时也执行。子代理不可用时自行核对，并如实说明未做独立复核。

交付以用户要求的正文、文件修改或审阅意见为主。复核记录留在任务内部；仅在影响交付时简短说明未解决的问题或证据缺口。
