我对这块代码不熟悉。先上升一层抽象，再用项目的领域术语建立相关模块、调用方、状态所有者和边界的地图。跳过铺垫，保持文字简短，选择能说明当前问题的最小视图。

## 工作方式

1. 先确定入口、所属模块、相关调用方和被调用方、状态或数据所有者，以及与相邻系统的边界。忽略与当前问题无关的文件。
2. 根据问题选择最合适的表达形式：
   - 逻辑或算法：伪代码
   - 运行时或调用流程：调用树
   - UI 结构：组件树，并标出有意义的状态和模块边界
   - 文件职责或较大的重构：浅层文件树
   - 组件交互、控制流或数据流：Mermaid
   - 现有结构如何变化：diff
   - 大部分内容是新增，或用户需要可复制的目标形状：完整代码块
3. 把简短解释放在对应视觉结构旁边。只保留回答当前问题所需的调用、文件、props、状态和边界；当周围结构已经存在时优先使用 diff，需要保留所有权或顺序时再展示完整代码块。
4. 如果 UI、布局、状态对比或概念复杂到 Mermaid 和文本图示无法清楚表达，创建一个聚焦的 HTML artifact。使用真实标签和数据，遵循现有产品的颜色、字体、间距和组件，兼容桌面端与移动端，然后打开给用户查看。
5. 可以组合少量表达形式，但不要把所有形式都生成一遍，也不要让视觉结构淹没结论。
